Obsługa błędów, Guard Clause i wyjątki

W poprzedniej lekcji napisałeś metodę ObliczSrednia(List<int> punkty). Działała świetnie dla 5 ocen. A co się stanie, gdy ktoś wywoła ją z pustą listą new List<int>() albo z wartością null?

Dla pustej listy wyrażenie (double)0 / 0 w C# nie wyrzuci błędu - zwróci po cichu dziwną wartość NaN (Not a Number), która potem trafi do bazy danych lub na świadectwo ucznia. W tej lekcji nauczysz się programowania defensywnego: jak zatrzymywać złe dane na granicy metody (Guard Clause) i jak bezpiecznie obsługiwać błędy blokiem try / catch / finally.

🛡️ Wzorzec Guard Clause (strażnik na wejściu metody)

Guard Clause to warunek ochronny umieszczony w pierwszych linijkach metody, zanim wykonasz jakiekolwiek obliczenia. Jeśli dane łamią regułę, metoda natychmiast rzuca wyjątek słowem throw i przerywa działanie (fail‑fast):

public static decimal ObliczCeneBiletu(int wiek, decimal cenaBazowa)
{
    if (wiek < 0 || wiek > 130)
        throw new ArgumentOutOfRangeException(nameof(wiek), "Wiek musi mieścić się w przedziale 0..130.");

    if (cenaBazowa <= 0m)
        throw new ArgumentOutOfRangeException(nameof(cenaBazowa), "Cena musi być dodatnia.");

    return wiek < 18 ? cenaBazowa * 0.5m : cenaBazowa;
}

Operator nameof(wiek) zamienia nazwę parametru na napis "wiek" sprawdzany przez kompilator - jeśli kiedyś zmienisz nazwę parametru, kompilator przypomni o poprawce.

📋 Który wyjątek wybrać? (Mapa decyzyjna C#)

Sytuacja błędu Standardowy wyjątek w C# Przykład użycia

✨ Wskazówka

Zauważ hierarchię w C#: zarówno ArgumentNullException, jak i ArgumentOutOfRangeException dziedziczą po ArgumentException. Jeśli więc test sprawdza ArgumentException, a Ty rzucisz bardziej szczegółowy ArgumentNullException, oba warunki zostaną spełnione!

🧯 Przechwytywanie błędów: try, catch i finally

Rzucanie wyjątków to jedna strona medalu (np. w metodzie bibliotecznej Dziennik.ObliczSrednia). Druga strona to obsługa wyjątku w kodzie wywołującym (np. w Main()), żeby aplikacja mogła pokazać użytkownikowi czytelny komunikat zamiast zamknąć się z awarią:

try
{
    var pusta = new List<int>();
    double srednia = Dziennik.ObliczSrednia(pusta);
    Console.WriteLine($"Średnia: {srednia:F2}");
}
catch (ArgumentException ex)
{
    // Łapiemy KONKRETNY typ wyjątku i odczytujemy jego komunikat ex.Message
    Console.WriteLine($"Niepoprawne dane: {ex.Message}");
}
finally
{
    // Blok finally wykonuje się ZAWSZE (czy był błąd, czy nie) - idealny do sprzątania zasobów
    Console.WriteLine("Zakończono analizę.");
}

⚠️ Antywzorzec: pusty catch (połykanie wyjątków)

Nigdy nie pisz catch (Exception) { } z pustym ciałem! Taki zapis ukrywa każdy błąd (łącznie z literówkami i błędami logiki), przez co aplikacja psuje dane w ciszy, a Ty godzinami szukasz przyczyny. Łap wyłącznie konkretne wyjątki, które potrafisz sensownie obsłużyć.

🔬 Pod maską: Stack Unwinding - dlaczego wyjątek kosztuje tysiące cykli CPU CLR & WYDAJNOŚĆ

Gdy w metodzie na głębokim poziomie stosu wywołań (np. Main -> Raport -> Dziennik -> ObliczSrednia) wykona się throw new ArgumentException(...), środowisko CLR uruchamia procedurę zwijania stosu (Stack Unwinding):

  1. CLR zatrzymuje normalny potok instrukcji procesora.
  2. Przeszukuje tablicę metadanych każdej kolejnej ramki na stosie (ObliczSrednia, potem Dziennik, potem Raport, aż do Main), szukając pasującego bloku catch.
  3. Po drodze wykonuje wszystkie napotkane bloki finally (np. zamykające pliki).
  4. Buduje obiekt StackTrace ze ścieżkami plików i numerami linii.

Ta operacja trwa dziesiątki mikrosekund - jest ok. 1000× wolniejsza niż zwykły if lub return false.

Złota zasada wydajności w .NET:

  • Wyjątki służą do sytuacji wyjątkowych (złamany kontrakt metody, brak pliku, zerwane połączenie).
  • Do codziennego parsowania danych od użytkownika (gdzie błędny wpis jest normalny) używaj bezwyjątkowego wzorca TryParse (np. int.TryParse(wejscie, out int liczba)), który działa w kilkanaście nanosekund bez żadnego Stack Unwinding.

public static double ObliczSrednia(List<int> oceny)
{
    if (oceny == null || oceny.Count == 0)
        throw new ArgumentException("Lista ocen nie może być pusta.");

    int suma = 0;
    foreach (int ocena in oceny)
    {
        if (ocena < 1 || ocena > 6)
            throw new ArgumentOutOfRangeException(nameof(oceny), "Ocena musi należeć do zakresu 1..6.");
        suma += ocena;
    }

    return (double)suma / oceny.Count;
}

public static int PoliczZaliczone(List<int> oceny, int prog)
{
    if (oceny == null) throw new ArgumentException("Lista ocen nie może być null.");
    if (prog < 1 || prog > 6) throw new ArgumentOutOfRangeException(nameof(prog));

    int licznik = 0;
    foreach (int ocena in oceny)
    {
        if (ocena >= prog) licznik++;
    }
    return licznik;
}

public static string BezpiecznaSredniaTekst(List<int> oceny)
{
    try
    {
        double s = ObliczSrednia(oceny);
        return $"{s:F2}";
    }
    catch (ArgumentException)
    {
        return "BŁĄD";
    }
}
