Listy generyczne List i pętla foreach

W poprzedniej lekcji poznałeś tablice int[], które są błyskawiczne, ale mają jedną poważną granicę: ich rozmiaru nie da się zmienić po utworzeniu. Jeśli tworzysz koszyk w sklepie albo dziennik ocen, nie wiesz na starcie, czy użytkownik doda 3 produkty, czy 47.

Gdy liczba elementów zmienia się w trakcie działania programu, sięgasz w C# po kolekcję generyczną List<T> oraz stworzoną do niej pętlę foreach.

📦 List jako dynamiczna tablica z gotowymi narzędziami

Aby używać List<T>, dodaj na górze pliku przestrzeń nazw:

using System.Collections.Generic;

Znak <T> oznacza typ generyczny - w miejsce T wpisujesz typ elementów, które lista ma trzymać (List<int>, List<string>, List<decimal>).

var oceny = new List<int> { 4, 5, 3 };

oceny.Add(6);               // Dodaje na koniec -> { 4, 5, 3, 6 }
oceny.Insert(0, 2);         // Wstawia na indeks 0 -> { 2, 4, 5, 3, 6 }
oceny.Remove(3);            // Usuwa PIERWSZE wystąpienie wartości 3 -> { 2, 4, 5, 6 }
oceny.RemoveAt(0);          // Usuwa element pod indeksem 0 -> { 4, 5, 6 }

int ile = oceny.Count;      // 3 (UWAGA: tablica ma .Length, a List<T> ma .Count!)
bool maPiatke = oceny.Contains(5); // true
oceny.Sort();               // Sortuje listę rosnąco w miejscu

🔎 Tablica `T[]` kontra `List` - szybka tabela decyzyjna

Cecha Tablica int[] Lista List<int>
Zmiana rozmiaru po utworzeniu Niemożliwa (stały blok RAM) Automatyczna (.Add(), .Remove())
Odczyt liczby elementów .Length .Count
Dostęp po indeksie tab[i] (czas $O(1)$) lista[i] (czas $O(1)$)
Kiedy wybierasz? Stały rozmiar (np. 7 dni tygodnia, plansza 3x3) Liczba elementów rośnie lub maleje w trakcie pracy

🔁 Pętla foreach - czytelne przechodzenie po kolekcji

Gdy chcesz przeczytać każdy element listy od pierwszego do ostatniego, nie musisz pilnować licznika int i = 0; i < oceny.Count; i++. Używasz pętli foreach:

var oceny = new List<int> { 2, 4, 5, 3, 5 };
int suma = 0;

foreach (int ocena in oceny)
{
    suma += ocena;
}

double srednia = (double)suma / oceny.Count; // 3.80 (pamiętaj o (double)!)

⚠️ Dwie twarde granice pętli foreach (kiedy wrócić do for?)

Pętla foreach jest świetna, ale nie zastępuje for w każdej sytuacji:

  1. Nie możesz podmienić elementu listy przez zmienną z foreach: zapis ocena = 6; wewnątrz foreach (int ocena in oceny) nie skompiluje się (zmienna iteracyjna jest tylko do odczytu). Jeśli chcesz podnieść każdą ocenę o 1, użyj for (int i = 0; i < oceny.Count; i++) { oceny[i]++; }.
  2. Nie możesz wywołać oceny.Add(...) ani oceny.Remove(...) podczas trwania foreach: kompilator to przepuści, ale w trakcie wykonania program wyrzuci InvalidOperationException: Collection was modified. Gdy chcesz przefiltrować listę, utwórz nową listę wynikową (var wynik = new List<int>();) i dodawaj do niej pasujące elementy!
🔬 Pod maską: Jak List rośnie w pamięci (Capacity 0 -> 4 -> 8 -> 16) i jak działa IEnumerator STRUKTURY DANYCH & CLR

List<T> nie jest żadną magiczną strukturą - w środku trzyma zwykłą tablicę T[] _items oraz dwa liczniki: _size (widoczne jako Count) i _items.Length (widoczne jako Capacity).

Zobacz, co dzieje się w pamięci RAM przy kolejnych wywołaniach .Add():

Operacja Count (zajęte) Capacity (rozmiar _items) Co robi CLR w pamięci?
new List<int>() 0 0 Pusta tablica współdzielona (0 alokacji)
1. .Add(10) 1 4 Alokuje nową tablicę int[4]
2..4. .Add(...) 2..4 4 Wpisuje w wolne sloty w czasie $O(1)$
5. .Add(50) 5 8 Alokuje int[8], kopiuje 4 elementy, dopisuje 5.
9. .Add(90) 9 16 Alokuje int[16], kopiuje 8 elementów, dopisuje 9.

Wskazówka wydajnościowa: jeśli z góry wiesz, że wczytasz z pliku 10 000 rekordów, napisz new List<int>(10000) - lista od razu zarezerwuje 10 000 miejsc i uniknie 12 zbędnych kopiowań tablicy i śmieci dla GC!

Dlaczego foreach rzuca InvalidOperationException przy .Remove()?
Każda List<T> posiada ukryte pole _version, zwiększane przy każdym Add / Remove. Pętla foreach pod maską tworzy obiekt IEnumerator<T>, który zapamiętuje _version z chwili startu pętli i przed każdym kolejnym MoveNext() sprawdza, czy wersja się nie zmieniła. Jeśli zmodyfikujesz listę w środku pętli, iterator natychmiast przerywa pracę, zanim przeczytałby błędne lub nieistniejące indeksy.

Sprawdź rozwiązanie po wykonaniu próby 
public static double ObliczSrednia(List<int> punkty)
{
    int suma = 0;
    foreach (int p in punkty)
    {
        suma += p;
    }
    return (double)suma / punkty.Count;
}

public static List<int> FiltrujPowyzejProgu(List<int> punkty, int prog)
{
    var wynik = new List<int>();
    foreach (int p in punkty)
    {
        if (p >= prog) wynik.Add(p);
    }
    return wynik;
}

public static void DodajBonus(List<int> punkty, int bonus)
{
    for (int i = 0; i < punkty.Count; i++)
    {
        punkty[i] += bonus;
    }
}

🦾🐨🦾 Co masz wynieść z tej lekcji:

  • Wybieraj List<T> zamiast tablicy T[], gdy liczba elementów zmienia się w trakcie działania programu; liczbę elementów odczytuj przez .Count.
  • Używaj foreach do czytania, sumowania i filtrowania do nowej listy; wracaj do for, gdy musisz modyfikować elementy w miejscu (lista[i] = ...) lub potrzebujesz numeru indeksu.
  • Nigdy nie dodawaj ani nie usuwaj elementów z kolekcji, po której aktualnie przechodzi pętla foreach.
