Dziedziczenie i polimorfizm

Masz już gotową, bezpieczną klasę KontoBankowe. Teraz bank wprowadza nowy produkt: konto oszczędnościowe, które ma oprocentowanie oraz pobiera 5 zł prowizji za każdą wypłatę. Gdybyś skopiował cały plik KontoBankowe.cs pod nową nazwą, każdą poprawkę musiałbyś nanosić w dwóch miejscach.

W OOP zamiast kopiować kod, budujesz hierarchię przez dziedziczenie (:) i zmieniasz zachowanie konkretnych metod przez polimorfizm (virtual / override).

🧬 Dziedziczenie: dwukropek i słowo base

Zapis class KontoOszczednosciowe : KontoBankowe wyraża relację „JEST” (is‑a): KontoOszczednosciowe przejmuje wszystkie public i protected właściwości oraz metody rodzica bez przepisywania ani jednej linijki.

public class KontoFirmowe : KontoBankowe
{
    public string Nip { get; }

    // : base(wlasciciel, saldo) przekazuje wspólne dane do konstruktora rodzica!
    public KontoFirmowe(string wlasciciel, decimal saldo, string nip)
        : base(wlasciciel, saldo)
    {
        Nip = nip;
    }

    // override przesłania metodę oznaczoną jako virtual w klasie bazowej
    public override bool Wyplac(decimal kwota)
    {
        // Możesz dodać własną regułę, a potem wywołać oryginał rodzica przez base.Wyplac(...)
        return base.Wyplac(kwota);
    }
}

⚠️ Pułapka 1: dlaczego Saldo miało protected set zamiast private set?

Gdyby Saldo w KontoBankowe było private set, to klasa potomna KontoOszczednosciowe nie miałaby prawa go zmodyfikować w metodzie NaliczOdsetki(). Modyfikator protected set otwiera zapis wyłącznie dla rodziny klas dziedziczących, nadal szczelnie blokując dostęp z zewnątrz (Program.cs).

🎭 Polimorfizm wykonawczy: jedna lista, różne zachowania

Wielu uczniów myli polimorfizm z przeciążaniem metod (overloading). Prawdziwy polimorfizm wykonawczy (runtime polymorphism) oznacza, że jedna pętla foreach wywołuje tę samą metodę na wspólnej liście typu bazowego, a każdy obiekt reaguje po swojemu:

var konta = new List<KontoBankowe>
{
    new KontoBankowe("Jan", 200m),
    new KontoOszczednosciowe("Anna", 200m, 0.05m)
};

foreach (KontoBankowe k in konta)
{
    k.Wyplac(50m); // Dla Jana zejdzie 50 zł, a dla Anny 55 zł (50 + 5 zł prowizji)!
    Console.WriteLine($"{k.Wlasciciel} ({k.GetType().Name}): {k.Saldo:F2} zł");
}

⚠️ Pułapka 2: override kontra ukrycie metody (new)

Jeśli w klasie potomnej zapomnisz napisać override (albo użyjesz słowa new zamiast override), stworzysz jedynie oddzielną metodę o tej samej nazwie. Wtedy wywołanie k.Wyplac(50m) przez zmienną typu KontoBankowe uruchomi starą metodę rodzica (bez prowizji 5 zł!) - polimorfizm zostanie całkowicie złamany!

🔎 Bezpieczne sprawdzanie konkretnego typu: operator is

Czasem w pętli po List<KontoBankowe> chcesz wywołać metodę, którą ma tylko klasa potomna (np. NaliczOdsetki()). Użyj wtedy bezpiecznego dopasowania wzorca is:

foreach (KontoBankowe k in konta)
{
    if (k is KontoOszczednosciowe oszcz)
    {
        oszcz.NaliczOdsetki(); // Wykona się bezpiecznie tylko dla kont oszczędnościowych!
    }
}
🔬 Pod maską: Tablica metod wirtualnych (vtable), call vs callvirt oraz optymalizacja sealed CLR & VTABLE

Skoro pętla foreach (KontoBankowe k in konta) widzi zmienną k wyłącznie jako typ KontoBankowe, skąd procesor w locie wie, że dla Anny ma skoczyć do KontoOszczednosciowe.Wyplac?

Każdy obiekt na stercie ma na pozycji +8 B wskaźnik do tablicy metod swojego prawdziwego typu (MethodTable / vtable):

Slot w vtable KontoBankowe (rodzic) KontoOszczednosciowe (dziecko z override)
Slot 0 (ToString) Object.ToString Object.ToString
Slot 4 (Wyplac) → KontoBankowe.Wyplac → KontoOszczednosciowe.Wyplac (podmieniony adres!)
  • Dla zwykłych metod (bez virtual) kompilator generuje statyczne wywołanie (static dispatch) - adres metody jest znany w czasie kompilacji.
  • Dla metod virtual kompilator generuje instrukcję CIL callvirt (dynamic dispatch) - procesor czyta wskaźnik MethodTable z obiektu w RAM, zagląda w Slot 4 i skacze pod znaleziony adres.
  • Słowo kluczowe sealed: jeśli oznaczysz klasę potomną jako public sealed class KontoOszczednosciowe, obiecujesz kompilatorowi, że nikt już po niej nie odziedziczy. Dzięki temu kompilator JIT może zastosować optymalizację devirtualization (ominąć skok przez vtable i nawet wkleić kod metody w miejscu wywołania!).

💻 Zadanie praktyczne (projekt 3-plikowy): KontoOszczednosciowe i polimorfizm

W edytorze masz trzy pliki: Program.cs, zablokowane do odczytu KontoBankowe.cs oraz plik KontoOszczednosciowe.cs, w którym uzupełnisz 3 zadania:

  1. Konstruktor KontoOszczednosciowe(...):
    • jeśli oprocentowanie < 0m, rzuć throw new ArgumentOutOfRangeException(nameof(oprocentowanie));.
  2. Metoda NaliczOdsetki():
    • zwiększ Saldo o Saldo * Oprocentowanie.
  3. Metoda override bool Wyplac(decimal kwota):
    • jeśli kwota <= 0m → rzuć throw new ArgumentOutOfRangeException(nameof(kwota));,
    • całkowity koszt wypłaty to kwota + 5m (prowizja 5 zł),
    • wywołaj return base.Wyplac(kwota + 5m); (metoda rodzica sama zablokuje debet, jeśli brakuje środków na kwotę razem z prowizją!).
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        var konta = new List<KontoBankowe>
        {
            new KontoBankowe("Jan", 200m),
            new KontoOszczednosciowe("Anna", 200m, 0.05m)
        };

        foreach (var k in konta)
        {
            k.Wyplac(50m);
            if (k is KontoOszczednosciowe oszcz)
            {
                oszcz.NaliczOdsetki();
            }
            Console.WriteLine($"{k.Wlasciciel} ({k.GetType().Name}): {k.Saldo:F2} zł");
        }
    }
}

using System;

public class KontoBankowe
{
    public string Wlasciciel { get; }
    public decimal Saldo { get; protected set; }

    public KontoBankowe(string wlasciciel, decimal saldoPoczatkowe = 0m)
    {
        if (string.IsNullOrWhiteSpace(wlasciciel)) throw new ArgumentException("Brak właściciela");
        if (saldoPoczatkowe < 0m) throw new ArgumentOutOfRangeException(nameof(saldoPoczatkowe));
        Wlasciciel = wlasciciel;
        Saldo = saldoPoczatkowe;
    }

    public void Wplac(decimal kwota)
    {
        if (kwota <= 0m) throw new ArgumentOutOfRangeException(nameof(kwota));
        Saldo += kwota;
    }

    public virtual bool Wyplac(decimal kwota)
    {
        if (kwota <= 0m) throw new ArgumentOutOfRangeException(nameof(kwota));
        if (kwota > Saldo) return false;
        Saldo -= kwota;
        return true;
    }
}

using System;

public class KontoOszczednosciowe : KontoBankowe
{
    public decimal Oprocentowanie { get; }

    public KontoOszczednosciowe(string wlasciciel, decimal saldoPoczatkowe, decimal oprocentowanie)
        : base(wlasciciel, saldoPoczatkowe)
    {
        // TODO 1: Jeśli oprocentowanie < 0m -> rzuć ArgumentOutOfRangeException
        Oprocentowanie = oprocentowanie;
    }

    public void NaliczOdsetki()
    {
        // TODO 2: Dodaj do Saldo kwotę Saldo * Oprocentowanie
    }

    public override bool Wyplac(decimal kwota)
    {
        // TODO 3: Waliduj kwota <= 0m, a potem wywołaj base.Wyplac(kwota + 5m)
        return base.Wyplac(kwota);

}

public class KontoOszczednosciowe : KontoBankowe
{
    public decimal Oprocentowanie { get; }

    public KontoOszczednosciowe(string wlasciciel, decimal saldoPoczatkowe, decimal oprocentowanie)
        : base(wlasciciel, saldoPoczatkowe)
    {
        if (oprocentowanie < 0m) throw new ArgumentOutOfRangeException(nameof(oprocentowanie));
        Oprocentowanie = oprocentowanie;
    }

    public void NaliczOdsetki()
    {
        Saldo += Saldo * Oprocentowanie;
    }

    public override bool Wyplac(decimal kwota)
    {
        if (kwota <= 0m) throw new ArgumentOutOfRangeException(nameof(kwota));
        return base.Wyplac(kwota + 5m);
    }
}

🦾🐨🦾 Co masz wynieść z tej lekcji:

  • Dziedziczenie (class Dziecko : Rodzic) stosuj wyłącznie przy relacji „JEST” i zawsze deleguj inicjalizację wspólnych danych przez : base(...).
  • Prawdziwy polimorfizm wykonawczy działa tylko dzięki parze virtual (w rodzicu) + override (w dziecku) - nigdy nie używaj ukrywania new do nadpisywania zachowania.
  • Gdy potrzebujesz sięgnąć po metodę specyficzną dla klasy potomnej, sprawdzaj typ bezpiecznym operatorem if (k is KontoOszczednosciowe oszcz).
