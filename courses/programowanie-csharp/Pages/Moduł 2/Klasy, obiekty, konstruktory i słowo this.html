Klasy, obiekty, konstruktory i słowo this

Wyobraź sobie, że tworzysz sklep internetowy z 50 produktami. Bez obiektów musiałbyś trzymać trzy osobne, niepowiązane listy: List<string> nazwy, List<decimal> ceny, List<int> ilosci. Jeśli usuniesz 12. element z nazwy, ale zapomnisz usunąć go z ceny, cały sklep zacznie sprzedawać laptopy w cenie kabla HDMI.

Programowanie Obiektowe (OOP) rozwiązuje ten chaos u źródła: wiąże dane i operacje na tych danych w jeden spójny organizm zwany obiektem, tworzony na podstawie szablonu - klasy (class).

🏠 Klasa (projekt) kontra Obiekt (konkretny egzemplarz)

  • Klasa (class) to projekt architektoniczny zapisany w osobnym pliku .cs (np. Produkt.cs). Sama klasa nie zajmuje jeszcze pamięci na dane konkretnego produktu - opisuje tylko, jakie właściwości i metody będzie mieć każdy egzemplarz.
  • Obiekt (instancja) to konkretny produkt utworzony w pamięci słowem kluczowym new. Z jednej klasy Produkt możesz utworzyć tysiąc niezależnych obiektów.

🔍 Pełna anatomia klasy: konstruktory, : this(...) i ToString()

Spójrz na kompletną klasę Bohater zapisaną w osobnym pliku Bohater.cs:

using System;

public class Bohater
{
    // 1. Właściwości instancyjne - każdy obiekt ma WŁASNĄ kopię tych danych
    public string Imie { get; }
    public int PunktyZycia { get; private set; }

    // 2. Właściwość statyczna (static) - JEDNA wspólna dla całej klasy!
    public static int LiczbaBohaterow { get; private set; } = 0;

    // 3. Konstruktor główny - uruchamia się przy "new Bohater(...)"
    public Bohater(string imie, int startoweHp)
    {
        if (string.IsNullOrWhiteSpace(imie)) throw new ArgumentException("Brak imienia");
        if (startoweHp < 0) throw new ArgumentOutOfRangeException(nameof(startoweHp));

        this.Imie = imie;            // słowo "this" wskazuje na bieżący obiekt
        this.PunktyZycia = startoweHp;
        LiczbaBohaterow++;
    }

    // 4. Przeciążenie konstruktora - deleguje pracę do głównego przez ": this(...)"
    public Bohater(string imie) : this(imie, 100) { }

    // 5. Metoda instancyjna (BEZ słowa static!) - działa na konkretnym obiekcie
    public void OtrzymajObrazenia(int ile)
    {
        if (ile < 0) throw new ArgumentOutOfRangeException(nameof(ile));
        PunktyZycia = Math.Max(0, PunktyZycia - ile);
    }

    // 6. Nadpisanie ToString() - decyduje, co wypisze Console.WriteLine(bohater)
    public override string ToString()
    {
        return $"{Imie} ({PunktyZycia} HP)";
    }
}

Zobacz, jak czysto używa się tej klasy w Program.cs:

var rycerz = new Bohater("Geralt", 120); // używa konstruktora 2-parametrowego
var uczen = new Bohater("Ciri");         // używa konstruktora 1-parametrowego (: this(..., 100))

rycerz.OtrzymajObrazenia(25);

Console.WriteLine(rycerz);               // automatycznie wywoła rycerz.ToString() -> "Geralt (95 HP)"
Console.WriteLine(uczen);                // "Ciri (100 HP)"
Console.WriteLine($"Łącznie bohaterów: {Bohater.LiczbaBohaterow}"); // 2 (wywołanie na KLASIE!)

⚠️ Pułapka: kiedy static, a kiedy metoda obiektu?

  • Jeśli metoda lub właściwość dotyczy jednego konkretnego obiektu (np. rycerz.OtrzymajObrazenia(25), rycerz.PunktyZycia) → NIE używaj static.
  • Jeśli dana dotyczy całego gatunku / fabryki (np. Bohater.LiczbaBohaterow, Math.Max(a, b)) → użyj static i odwołuj się przez nazwę klasy, a nie obiektu.
🔬 Pod maską: Jak obiekt wygląda na stercie CLR i czym naprawdę jest słowo this OOP & PAMIĘĆ CLR

Gdy wykonujesz var rycerz = new Bohater("Geralt", 120);, środowisko CLR przydziela na stercie RAM ciągły blok bajtów o ściśle określonym układzie (na architekturze 64‑bitowej):

Przesunięcie Rozmiar Zawartość w pamięci obiektu
+0 B 8 B Object Header (SyncBlockIndex - używany przy blokadach wątków i hashowaniu)
+8 B 8 B MethodTable Pointer (adres opisu klasy Bohater i tablicy jej metod!)
+16 B 8 B Pole Imie (adres referencji do napisu "Geralt")
+24 B 4 B Pole PunktyZycia (liczba 120) + 4 B wyrównania (padding)

Zauważ rzecz kluczową: kod metody OtrzymajObrazenia NIE jest kopiowany do każdego obiektu! Istnieje tylko raz w pamięci klasy. Gdy piszesz rycerz.OtrzymajObrazenia(25), kompilator tłumaczy to na wywołanie z ukrytym pierwszym parametrem this:

// Co piszesz w C#:
rycerz.OtrzymajObrazenia(25);

// Co naprawdę wykonuje CLR:
Bohater.OtrzymajObrazenia(this: rycerz, ile: 25);

Dlatego metoda static nie może odczytać PunktyZycia - w jej ramce na stosie po prostu nie ma ukrytego parametru this!

W edytorze masz dwa osobne pliki: Program.cs oraz Produkt.cs. Kliknij zakładkę Produkt.cs i uzupełnij klasę:

  1. Konstruktor główny Produkt(string nazwa, decimal cena, int ilosc):
    • jeśli string.IsNullOrWhiteSpace(nazwa) → rzuć ArgumentException,
    • jeśli cena <= 0m lub ilosc < 0 → rzuć ArgumentOutOfRangeException,
    • zapisz Nazwa, Cena, Ilosc.
  2. Konstruktor skrócony Produkt(string nazwa, decimal cena) : this(nazwa, cena, 1):
    • deleguje do głównego konstruktora z domyślną ilością 1.
  3. Metoda ObliczWartoscMagazynu():
    • zwraca Cena * Ilosc.
  4. Metoda ZmienCene(decimal nowaCena):
    • jeśli nowaCena <= 0m → rzuć ArgumentOutOfRangeException, inaczej ustaw Cena = nowaCena;.
  5. Metoda override string ToString():
    • zwraca dokładnie $"{Nazwa}: {Cena:F2} zł (szt: {Ilosc})".

Sprawdź rozwiązanie po wykonaniu próby 
public Produkt(string nazwa, decimal cena, int ilosc)
{
    if (string.IsNullOrWhiteSpace(nazwa)) throw new ArgumentException("Brak nazwy produktu.");
    if (cena <= 0m) throw new ArgumentOutOfRangeException(nameof(cena));
    if (ilosc < 0) throw new ArgumentOutOfRangeException(nameof(ilosc));

    Nazwa = nazwa;
    Cena = cena;
    Ilosc = ilosc;
}

public decimal ObliczWartoscMagazynu() => Cena * Ilosc;

public void ZmienCene(decimal nowaCena)
{
    if (nowaCena <= 0m) throw new ArgumentOutOfRangeException(nameof(nowaCena));
    Cena = nowaCena;
}

public override string ToString()
{
    return $"{Nazwa}: {Cena:F2} zł (szt: {Ilosc})";
}

🦾🐨🦾 Co masz wynieść z tej lekcji:

  • Każda klasa leży we własnym pliku .cs; konstruktor gwarantuje, że obiekt od pierwszej milisekundy powstaje w poprawnym stanie.
  • Przeciążone konstruktory łącz przez : this(...), aby nie kopiować kodu walidacji w dwóch miejscach.
  • Metody i właściwości konkretnego egzemplarza pisz bez static; słowo static rezerwuj dla danych wspólnych dla całej klasy.
  • Nadpisuj override string ToString(), aby obiekty same potrafiły wypisać się w czytelnej formie podczas debugowania i w konsoli.
