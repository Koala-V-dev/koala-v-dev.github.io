Słowniki Dictionary i wyszukiwanie w czasie O(1)

Wyobraź sobie, że masz w folderze 5 000 plików i chcesz błyskawicznie przypisać każdemu rozszerzeniu (.png, .jpg, .pdf, .zip, .exe) właściwy folder docelowy albo zliczyć, ile razy wystąpił każdy skrót SHA‑256. Przeszukiwanie listy w pętli dla każdego pliku zajęłoby miliony porównań ($O(n^2)$).

Rozwiązaniem jest Dictionary<TKey, TValue> - tablica haszująca, która zamienia dowolny klucz na jego wartość w stałym czasie $O(1)$, niezależnie od tego, czy słownik ma 10, czy 1 000 000 wpisów.

🔑 Jak słownik znajduje wartość bez przeszukiwania pętli?

Gdy pytasz słownik o klucz ".png", C# wylicza z niego liczbę całkowitą funkcją GetHashCode(), dzieli ją modulo przez liczbę kubełków i w jednym skoku trafia dokładnie do właściwego slotu:

Odczytaj ze schematu: w Dictionary<TKey, TValue> klucze muszą być unikalne (próba ponownego wywołania .Add(".png", ...) rzuci ArgumentException), natomiast wartości mogą się powtarzać (zarówno .png, jak i .jpg mogą wskazywać na "Obrazy").

🔹 Bezpieczny odczyt przez TryGetValue (nigdy na ślepo slownik[klucz]!)

Jeśli odwołasz się do nieistniejącego klucza przez kategorie[".xyz"], program natychmiast przerwie działanie wyjątkiem KeyNotFoundException. Profesjonalny wzorzec to TryGetValue:

var kategorie = new Dictionary<string, string>(StringComparer.OrdinalIgnoreCase)
{
    { ".png", "Obrazy" },
    { ".jpg", "Obrazy" },
    { ".pdf", "Dokumenty" },
    { ".zip", "Archiwa" }
};

string folder;
if (!kategorie.TryGetValue(".PNG", out folder))
{
    folder = "Inne";
}
// folder == "Obrazy" (dzięki StringComparer.OrdinalIgnoreCase ignoruje wielkość liter!)

🔹 Klasyczny wzorzec licznika wystąpień (Histogram / Częstość)

var licznik = new Dictionary<string, int>(StringComparer.OrdinalIgnoreCase);
foreach (string kat in listaKategorii)
{
    int ile;
    licznik.TryGetValue(kat, out ile); // Jeśli brak klucza, ile = 0
    licznik[kat] = ile + 1;            // Operator [] bezpiecznie dodaje LUB nadpisuje!
}
🔬 Pod maską: Kolizje hashy, Load Factor, dlaczego rozmiar kubełków to liczba pierwsza i C++ unordered_map TABLICE HASZUJĄCE · MATEMATYKA · CLR

1. Co się dzieje, gdy dwa różne klucze wpadną do tego samego kubełka (Kolizja)?
Ponieważ GetHashCode() zwraca 32‑bitowy int, a możliwych napisów jest nieskończenie wiele (zasada szufladkowa Dirichleta), dwa różne klucze mogą trafić w ten sam indeks hash % buckets.Length.
W .NET klasa Dictionary<TKey, TValue> rozwiązuje kolizje przez łańcuchowanie wewnątrz płaskiej tablicy struktur Entry[] (każdy wpis ma pole next wskazujące na kolejny indeks w tym samym kubełku - brak osobnych alokacji węzłów na stercie jak w std::unordered_map w C++!).

2. Dlaczego Dictionary wybiera rozmiary będące liczbami pierwszymi (3, 7, 17, 37, 71...)?
Gdy dane mają regularne wzorce (np. adresy podzielne przez 4 lub 8), dzielenie modulo przez potęgę dwójki skupiałoby wszystkie wpisy w kilku kubełkach. Dzielenie przez liczbę pierwszą równomiernie rozrzuca klucze po całej tablicy, utrzymując średni czas dostępu blisko $O(1)$.

3. Kontrakt GetHashCode() i Equals()
Jeśli dwa obiekty są równe (a.Equals(b) == true), ich skróty GetHashCode() muszą być identyczne. Złamanie tej reguły w własnych klasach powoduje, że obiekt włożony do słownika „znika” - ContainsKey szuka go w złym kubełku!

💻 Zadanie praktyczne: Silnik kategoryzacji i zliczania rozszerzeń

W klasie AnalizatorRozszerzen zaimplementuj dwie metody:

  1. PobierzKategorie(string rozszerzenie):
    • użyj Dictionary<string, string>(StringComparer.OrdinalIgnoreCase) z mapowaniem:
      • .png, .jpg, .webp → "Obrazy",
      • .pdf, .docx, .txt → "Dokumenty",
      • .zip, .7z, .rar → "Archiwa",
      • .exe, .msi → "Instalatory",
    • dla każdego innego rozszerzenia zwróć "Inne".
  2. ZliczKategorie(List<string> rozszerzenia):
    • zwróć Dictionary<string, int>, gdzie kluczem jest nazwa kategorii, a wartością liczba plików z tej kategorii.

        return "Inne";
    }

    {
        // Zlicz wystąpienia każdej kategorii w Dictionary<string, int>
        return new Dictionary<string, int>();
    }

    static void Main()
    {
        var ext = new List<string> { ".png", ".JPG", ".pdf", ".zip", ".mp3" };

Sprawdź rozwiązanie po wykonaniu własnej próby 
using System;
using System.Collections.Generic;

public class AnalizatorRozszerzen
{
    private static readonly Dictionary<string, string> Mapa = new Dictionary<string, string>(StringComparer.OrdinalIgnoreCase)
    {
        { ".png", "Obrazy" }, { ".jpg", "Obrazy" }, { ".webp", "Obrazy" },
        { ".pdf", "Dokumenty" }, { ".docx", "Dokumenty" }, { ".txt", "Dokumenty" },
        { ".zip", "Archiwa" }, { ".7z", "Archiwa" }, { ".rar", "Archiwa" },
        { ".exe", "Instalatory" }, { ".msi", "Instalatory" }
    };

    public static string PobierzKategorie(string rozszerzenie)
    {
        if (string.IsNullOrEmpty(rozszerzenie)) return "Inne";
        string kat;
        return Mapa.TryGetValue(rozszerzenie, out kat) ? kat : "Inne";
    }

    public static Dictionary<string, int> ZliczKategorie(List<string> rozszerzenia)
    {
        var wynik = new Dictionary<string, int>();
        foreach (string ext in rozszerzenia)
        {
            string kat = PobierzKategorie(ext);
            int ile;
            wynik.TryGetValue(kat, out ile);
            wynik[kat] = ile + 1;
        }
        return wynik;
    }

    static void Main()
    {
        var ext = new List<string> { ".png", ".JPG", ".pdf", ".zip", ".mp3" };
        var raport = ZliczKategorie(ext);
        foreach (var para in raport)
        {
            Console.WriteLine(para.Key + ": " + para.Value);
        }
    }
}

🦾🐨🦾 Co masz wynieść z tej lekcji:

  • Dictionary<TKey, TValue> daje wyszukiwanie w średnim czasie $O(1)$ dzięki tablicy haszującej (GetHashCode).
  • Zawsze odczytuj niepewne klucze przez TryGetValue, aby uniknąć KeyNotFoundException, a dla kluczy tekstowych używaj StringComparer.OrdinalIgnoreCase.
  • Zapis slownik[klucz] = wartosc bezpiecznie wstawia nowy klucz lub aktualizuje istniejący.
