Zmienne, typy danych i pułapki liczb

W 2014 roku licznik wyświetleń teledysku Gangnam Style na YouTube przekroczył 2 147 483 647 i zmusił inżynierów Google do pilnej migracji typu z 32‑bitowego na 64‑bitowy. W klasycznym Pac‑Manie dotarcie do 256. planszy psuje całą połowę ekranu, bo licznik poziomów mieści się w jednym bajcie (0..255).

W C# zmienna nie jest abstrakcyjnym „pudełkiem na cokolwiek”. To konkretny obszar pamięci RAM o sztywnej szerokości w bajtach i ściśle określonej interpretacji bitów. Jeśli wybierzesz zły typ albo zignorujesz reguły dzielenia, program skompiluje się bez ostrzeżeń i zwróci cicho zafałszowany wynik.

📦 Mapa typów w C# i ich rozmiar w pamięci

Zanim zapiszesz pierwszą liczbę, spójrz na to, ile bajtów poszczególne typy zajmują w pamięci operacyjnej i co dzieje się, gdy przekroczysz ich maksymalny zakres:

Porównaj szerokość pasków po lewej z licznikiem po prawej: decimal zajmuje aż 16 bajtów (4 razy więcej niż int), ale w zamian przechowuje ułamki dziesiętne bez błędów zaokrągleń binarnych.

Typ C# Rozmiar Zakres / przeznaczenie Przykład deklaracji
byte 1 B Liczby całkowite 0 .. 255 (kanał RGB, bajt pliku) byte red = 255;
int 4 B Domyślny typ całkowity (-2 147 483 648 .. +2 147 483 647) int punkty = 1500;
long 8 B Wielkie liczby całkowite (rozmiary dysków w bajtach, znaczniki czasu) long bajty = 50_000_000_000L;
double 8 B Zmiennoprzecinkowe (fizyka gier, współrzędne, prędkości, pomiary) double predkosc = 94.5;
decimal 16 B Dokładna arytmetyka dziesiętna (wymaga przyrostka m) decimal stawka = 19.99m;
bool 1 B Wartość logiczna: wyłącznie true lub false bool czyAdmin = false;
char 2 B Pojedynczy znak Unicode w apostrofach ' ' char znak = 'A';
string zmienny Ciąg znaków w cudzysłowach " " string host = "PC-01";

💬 Notatka

Podkreślniki w liczbach (np. 1_000_000 albo 0xFF_00_AA) są całkowicie ignorowane przez kompilator - służą wyłącznie czytelności dla człowieka.

⚠️ Trzy pułapki arytmetyczne, na których wykłada się każdy początkujący

Zanim uruchomisz poniższe przypadki w głowie, spróbuj przewidzieć, co wypisze C#, a dopiero potem skonfrontuj to z rzeczywistością.

🔹 1. Pułapka dzielenia całkowitego (int / int)

W C# wynik działania zależy od typów argumentów, a nie od typu zmiennej, do której go przypisujesz:

double wynikZly = 5 / 2;         // 5 i 2 to int! Dzielenie daje 2, dopiero potem staje się 2.0
double wynikDobry = 5.0 / 2;     // 2.5 (jedna strona jest double)
double wynikRzut = (double)5 / 2; // 2.5 (jawne rzutowanie przed dzieleniem)

Część ułamkowa w dzieleniu int / int jest bezwzględnie obcinana w stronę zera (nie zaokrąglana!). 9 / 10 w int to 0, a nie 1.

🔹 2. Operator reszty z dzielenia (% - modulo)

Operator % zwraca resztę z dzielenia całkowitego. To jedno z najważniejszych narzędzi w programowaniu gier i algorytmów:

  • przeliczanie sekund na godziny, minuty i sekundy (sekundy / 60 i sekundy % 60),
  • sprawdzanie parzystości (n % 2 == 0),
  • zawijanie współrzędnych lub alfabetu w szyfrach ((pozycja + przesuniecie) % 26).
int calkowiteSekundy = 3725;
int godziny = calkowiteSekundy / 3600;         // 1
int reszta = calkowiteSekundy % 3600;          // 125
int minuty = reszta / 60;                      // 2
int sekundy = reszta % 60;                     // 5
// Wynik: 01:02:05

🔹 3. Błąd binarny double (0.1 + 0.2 != 0.3)

Komputer przechowuje typ double w systemie dwójkowym (standard IEEE 754). Ułamek dziesiętny 0.1 w zapisie binarnym jest nieskończonym ułamkiem okresowym (0.0001100110011...), dokładnie tak jak 1/3 w systemie dziesiętnym (0.33333...). Dlatego w C#:

Console.WriteLine(0.1 + 0.2 == 0.3);     // False! (0.30000000000000004)
Console.WriteLine(0.1m + 0.2m == 0.3m);  // True!  (decimal liczy dziesiętnie)

🔢 Systemy liczbowe w C# (DEC, BIN, HEX)

C# pozwala zapisywać liczby bezpośrednio w systemie binarnym (0b...) i szesnastkowym (0x...) oraz formatować dowolną liczbę za pomocą Convert.ToString(liczba, baza):

int kolorHex = 0xFF;        // 255 (szesnastkowo)
int maskaBin = 0b1010_0101; // 165 (binarnie)

Console.WriteLine(Convert.ToString(42, 2));  // "101010" (BIN)
Console.WriteLine(Convert.ToString(42, 16)); // "2a"     (HEX)
🔬 Pod maską: Kod U2, IEEE 754, rozkaz IDIV w asemblerze x86-64 i blok checked ARCHITEKTURA CPU · ASM · C++

1. Dlaczego int.MaxValue + 1 daje liczbę ujemną (-2 147 483 648)?
Liczby ze znakiem (int, long) kodowane są w kodzie uzupełnień do dwóch (U2). Najstarszy bit (bit 31 w int) ma wagę ujemną $-2^{31}$.

  • int.MaxValue = 0111 1111 1111 1111 1111 1111 1111 1111 ($+2\,147\,483\,647$).
  • Po dodaniu 1 bit przeniesienia wchodzi na pozycję 31: 1000 0000 ... 0000 ($-2\,147\,483\,648$).

W C++ przepełnienie typu int ze znakiem to Undefined Behavior (UB) - kompilator ma prawo zoptymalizować kod w nieprzewidywalny sposób! W C# zachowanie jest w pełni zdefiniowane: domyślnie działa arytmetyka modularna (unchecked), a otoczenie działania blokiem checked { int x = max + 1; } zmusza CPU do sprawdzenia flagi OF (Overflow Flag) i rzucenia wyjątku OverflowException.

2. Dlaczego a / b i a % b to na procesorze JEDNA instrukcja?
Na architekturze x86‑64 instrukcja dzielenia całkowitego IDIV przyjmuje dzielną w rejestrach EDX:EAX i jednocześnie zapisuje:

  • iloraz (a / b) w rejestrze EAX,
  • resztę (a % b) w rejestrze EDX.

Nowoczesny kompilator JIT (oraz gcc -O2 w C++) potrafi rozpoznać, że liczysz sekundy / 60 i sekundy % 60 z tej samej liczby, a dzielenie przez stałą zastępuje jeszcze szybszym mnożeniem przez odwrotność stałoprzecinkową (IMUL + przesunięcie bitowe SAR), bo samo IDIV kosztuje 20‑40 cykli zegara!

3. Anatomia 64‑bitowego double (IEEE 754 binary64)
64 bity double dzielą się na: 1 bit znaku ($s$), 11 bitów wykładnika ($e$ z biasem 1023) i 52 bity mantysy ($m$). Wartość liczby to $(-1)^s \cdot (1 + m) \cdot 2^{e - 1023}$. Ponieważ mantysa koduje wyłącznie ułamki o mianownikach będących potęgami dwójki ($1/2, 1/4, 1/8, \dots$), ułamek $1/10 = 1/(2 \cdot 5)$ nigdy nie ma skończonego zapisu binarnego.

💻 Zadanie praktyczne: Kalkulator czasu pobierania i konwerter BIN/HEX

Napisz program kalkulujący realny czas pobrania pliku gry o rozmiarze 45 GB przy łączu 200 Mbps (megabitów na sekundę!) oraz wypisujący wartość rozmiaru w systemie binarnym i szesnastkowym.

Pamiętaj o kluczowej różnicy jednostek sieciowych: 1 bajt (B) = 8 bitów (b)!

  • 1 GB = 1024 MB (w obliczeniach systemowych), więc 45 GB = 46 080 MB.
  • Łącze 200 Mbps pobiera realnie 200 / 8 = 25 MB/s.
  • Czas w sekundach: 46080 / 25 = 1843 sekundy (użyj dzielenia całkowitego lub zaokrąglenia w dół (int)).

W metodzie Main() oblicz i wypisz dokładnie trzy linie:

  1. Predkosc: 25.0 MB/s (użyj string.Format(CultureInfo.InvariantCulture, ...) lub stałego formatu z kropką)
  2. Czas: 00:30:43 (format HH:MM:SS z zerami wiodącymi {0:D2} wyliczony przez / oraz %)
  3. 45 GB -> BIN: 101101 | HEX: 2D (użyj Convert.ToString(45, 2) oraz Convert.ToString(45, 16).ToUpper())
using System;
using System.Globalization;

class Program
{
    static void Main()
    {
        int rozmiarGb = 45;
        int laczeMbps = 200;

        // 1. Przelicz Mbps -> MB/s (double) oraz rozmiarGb -> MB
        // 2. Oblicz całkowite sekundy i rozbij na godziny, minuty, sekundy (/ oraz %)
        // 3. Wypisz 3 wymagane linie (użyj CultureInfo.InvariantCulture dla kropki w 25.0)
    }
}

LabAssert.Test("Kalkulator poprawnie przelicza Mbps -> MB/s, czas HH:MM:SS oraz BIN/HEX", () => {
    string output = LabAssert.RunMainAndCapture().TrimEnd();
    string[] lines = output.Split('\n');
    LabAssert.Equal(3, lines.Length);
    LabAssert.Equal("Predkosc: 25.0 MB/s", lines[0]);
    LabAssert.Equal("Czas: 00:30:43", lines[1]);
    LabAssert.Equal("45 GB -> BIN: 101101 | HEX: 2D", lines[2]);
});
Sprawdź rozwiązanie po wykonaniu własnej próby 
using System;
using System.Globalization;

class Program
{
    static void Main()
    {
        int rozmiarGb = 45;
        int laczeMbps = 200;

        double predkoscMBs = (double)laczeMbps / 8.0;
        int rozmiarMb = rozmiarGb * 1024;
        int calkowiteSekundy = (int)(rozmiarMb / predkoscMBs);

        int godziny = calkowiteSekundy / 3600;
        int minuty = (calkowiteSekundy % 3600) / 60;
        int sekundy = calkowiteSekundy % 60;

        Console.WriteLine(string.Format(CultureInfo.InvariantCulture, "Predkosc: {0:F1} MB/s", predkoscMBs));
        Console.WriteLine(string.Format("Czas: {0:D2}:{1:D2}:{2:D2}", godziny, minuty, sekundy));
        Console.WriteLine(string.Format("{0} GB -> BIN: {1} | HEX: {2}",
            rozmiarGb,
            Convert.ToString(rozmiarGb, 2),
            Convert.ToString(rozmiarGb, 16).ToUpper()));
    }
}

🦾🐨🦾 Co masz wynieść z tej lekcji:

  • Dzielenie dwóch liczb typu int zawsze obcina część ułamkową - rzutuj co najmniej jedną stronę na double przed dzieleniem ((double)a / b).
  • Operator % (modulo) w parze z / rozbija sekundy na HH:MM:SS, wyznacza współrzędne na planszy i zawija indeksy w szyfrach.
  • Wybieraj int do liczników, long do rozmiarów plików/dysków w bajtach, double do obliczeń fizycznych i pomiarów, a decimal wszędzie tam, gdzie ułamek dziesiętny musi być absolutnie dokładny.
  • Convert.ToString(n, 2) i Convert.ToString(n, 16) zamieniają liczby całkowite na zapis binarny i szesnastkowy.
