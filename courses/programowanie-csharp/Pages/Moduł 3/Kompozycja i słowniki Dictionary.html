Kompozycja i słowniki Dictionary

Masz już klasy kont i interfejsy. Teraz Twój bank ma 50 000 klientów i musi błyskawicznie znaleźć konto o numerze "PL-0042", żeby wykonać przelew. Przeszukiwanie listy List<KontoBankowe> pętlą foreach od początku do końca byłoby wolne. W tej lekcji połączysz kompozycję obiektów (relacja „MA”) ze słownikiem Dictionary<TKey, TValue>.

🗂️ Słownik Dictionary - wyszukiwanie po kluczu

Dictionary<TKey, TValue> (z przestrzeni System.Collections.Generic) przechowuje pary klucz → wartość (jak książka telefoniczna: numer konta → obiekt KontoBankowe).

var konta = new Dictionary<string, KontoBankowe>();

// Dodawanie pod unikalnym kluczem
konta["PL-01"] = new KontoBankowe("Jan", 500m);

// Bezpieczne wyszukiwanie bez rzucania wyjątku KeyNotFoundException:
if (konta.TryGetValue("PL-01", out KontoBankowe znalezione))
{
    Console.WriteLine($"Saldo Jana: {znalezione.Saldo} zł");
}

⚠️ Pułapka: indeksator kontra TryGetValue

Jeśli spróbujesz odczytać nieistniejący klucz przez konta["PL-99"], program natychmiast przerwie się błędem KeyNotFoundException. Metoda TryGetValue(klucz, out var wynik) jest bezpieczna: zwraca true i wpisuje obiekt do wynik, albo zwraca false bez błędu.

🧩 Kompozycja („MA”) zamiast nadużywania dziedziczenia

Klasa Bank nie dziedziczy po KontoBankowe (bank nie jest kontem!). Klasa Bank posiada (komponuje) słownik kont private readonly Dictionary<string, KontoBankowe> _konta. To jest wzorzec kompozycji: obiekt wyższego poziomu koordynuje współpracę wielu mniejszych obiektów (np. przelew z konta A na konto B).

🔬 Pod maską: Tablica haszująca (buckets + entries) w Dictionary - dlaczego wyszukiwanie trwa O(1) ALGORYTMY & HASHING

Gdy szukasz konta w List<KontoBankowe> o 1 000 000 elementów, pętla foreach musi w najgorszym razie sprawdzić wszystkie 1 000 000 pozycji (złożoność $O(n)$).

Dictionary<TKey, TValue> wewnątrz .NET utrzymuje dwie tablice: int[] buckets (kubełki) oraz Entry[] entries (wpisy z kluczem, wartością i hashem):

Krok wyszukiwania TryGetValue("PL-0042", ...) Operacja wykonywana przez CLR Koszt
1. Obliczenie hasha int hash = "PL-0042".GetHashCode() & 0x7FFFFFFF; $O(1)$
2. Wyznaczenie kubełka int bucketIndex = hash % buckets.Length; $O(1)$
3. Odczyt wpisu Skok do entries[buckets[bucketIndex]] i sprawdzenie Equals $O(1)$

Co się dzieje przy kolizji? Gdy dwa różne klucze wpadną w ten sam kubełek, Dictionary łączy je w krótką listę w tablicy entries przez pole next (tzw. separate chaining). Gdy słownik robi się zbyt pełny, .NET automatycznie powiększa tablicę buckets do kolejnej liczby pierwszej (np. $3 \to 7 \to 17 \to 37 \dots$) i przelicza pozycje (rehashing).

Złota zasada inżynierska: nigdy nie używaj jako klucza obiektu, którego pola zmieniają się po wstawieniu do Dictionary - po zmianie GetHashCode() zwróci inny kubełek i obiekt stanie się niewidzialny w słowniku!

W pliku Bank.cs uzupełnij klasę zarządzającą słownikiem kont _konta:

  1. DodajKonto(string numer, KontoBankowe konto):
    • jeśli string.IsNullOrWhiteSpace(numer) lub konto == null → rzuć ArgumentException,
    • jeśli _konta.ContainsKey(numer) → rzuć ArgumentException("Konto o tym numerze już istnieje"),
    • w przeciwnym razie zapisz _konta[numer] = konto;.
  2. ZnajdzKonto(string numer):
    • użyj _konta.TryGetValue(numer, out var konto) - zwróć znalezione konto lub null, jeśli nie istnieje.
  3. WykonajPrzelew(string zNumeru, string naNumer, decimal kwota):
    • jeśli zNumeru == naNumer lub kwota <= 0m → zwróć false,
    • znajdź oba konta przez TryGetValue; jeśli któregokolwiek brak → zwróć false,
    • najpierw spróbuj wykonać zrodlo.Wyplac(kwota): tylko jeśli zwróci true, wywołaj cel.Wplac(kwota) i zwróć true (atomowość: nie wolno dopisać pieniędzy odbiorcy, gdy nadawca nie miał środków!).
  4. SumaWszystkichSald():
    • przejdź pętlą foreach (var para in _konta) po wszystkich parach KeyValuePair<string, KontoBankowe> (albo po _konta.Values) i zwróć łączną sumę sald wszystkich kont w banku.

using System;

public class KontoBankowe
{
    public string Wlasciciel { get; }
    public decimal Saldo { get; protected set; }

    public KontoBankowe(string wlasciciel, decimal saldoPoczatkowe = 0m)
    {
        if (string.IsNullOrWhiteSpace(wlasciciel)) throw new ArgumentException("Brak właściciela");
        if (saldoPoczatkowe < 0m) throw new ArgumentOutOfRangeException(nameof(saldoPoczatkowe));
        Wlasciciel = wlasciciel;
        Saldo = saldoPoczatkowe;
    }

    public void Wplac(decimal kwota)
    {
        if (kwota <= 0m) throw new ArgumentOutOfRangeException(nameof(kwota));
        Saldo += kwota;
    }

    public virtual bool Wyplac(decimal kwota)
    {
        if (kwota <= 0m) throw new ArgumentOutOfRangeException(nameof(kwota));
        if (kwota > Saldo) return false;
        Saldo -= kwota;
        return true;
    }
}

public void DodajKonto(string numer, KontoBankowe konto)
{
    if (string.IsNullOrWhiteSpace(numer) || konto == null)
        throw new ArgumentException("Niepoprawne dane konta.");
    if (_konta.ContainsKey(numer))
        throw new ArgumentException("Konto o takim numerze już istnieje.");

    _konta[numer] = konto;
}

public KontoBankowe ZnajdzKonto(string numer)
{
    if (string.IsNullOrWhiteSpace(numer)) return null;
    return _konta.TryGetValue(numer, out var konto) ? konto : null;
}

public bool WykonajPrzelew(string zNumeru, string naNumer, decimal kwota)
{
    if (kwota <= 0m || zNumeru == naNumer) return false;
    if (!_konta.TryGetValue(zNumeru, out var zrodlo)) return false;
    if (!_konta.TryGetValue(naNumer, out var cel)) return false;

    if (!zrodlo.Wyplac(kwota)) return false;
    cel.Wplac(kwota);
    return true;
}

public decimal SumaWszystkichSald()
{
    decimal suma = 0m;
    foreach (var konto in _konta.Values)
    {
        suma += konto.Saldo;
    }
    return suma;
}

🦾🐨🦾 Co masz wynieść z tej lekcji:

  • Gdy szukasz obiektów po unikalnym identyfikatorze (numerze konta, PESEL‑u, kodzie produktu), wybieraj Dictionary<TKey, TValue> zamiast List<T> i odczytuj wartości przez TryGetValue.
  • Stosuj kompozycję (Bank posiada _konta) zawsze wtedy, gdy między obiektami zachodzi relacja „MA”, a nie „JEST”.
  • W operacjach zmieniających dwa obiekty naraz (np. przelew) zachowaj atomowość: najpierw zweryfikuj i wykonaj Wyplac, a dopiero po sukcesie wykonaj Wplac.
