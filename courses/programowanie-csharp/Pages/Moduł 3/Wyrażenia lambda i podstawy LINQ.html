Wyrażenia lambda i podstawy LINQ

Do tej pory, kiedy chciałeś z listy produktów wybrać tylko te droższe niż 100 zł, posortować je od najdroższego i wyciągnąć same nazwy, musiałeś napisać 20 linijek pętli foreach, warunków if, list tymczasowych i sortowania.

W nowoczesnym C# tę samą operację zapisuje się w czterech czytelnych linijkach za pomocą wyrażeń lambda oraz LINQ (Language Integrated Query). To jedna z najbardziej lubianych funkcji całego języka C#.

⚡ Wyrażenie lambda - mini-funkcja bez nazwy

Wyrażenie lambda to krótki zapis funkcji w jednej linijce z operatorem strzałki => (czytaj: „dla danego elementu zwróć...”):

// Zwykła metoda:
static bool CzyDrogi(Produkt p) { return p.Cena > 100m; }

// Dokładnie to samo jako wyrażenie lambda:
p => p.Cena > 100m

Po lewej stronie => stoi nazwa parametru (np. p), a po prawej wyrażenie, które ma zostać obliczone dla tego parametru.

🔗 Potoki LINQ (wymaga using System.Linq;)

Dzięki using System.Linq; każda lista List<T> i tablica T[] zyskuje zestaw metod rozszerzających, które możesz łączyć jedna za drugą w czytelny potok przetwarzania danych:

using System.Linq;

var drogieNazwy = produkty
    .Where(p => p.Cena >= 100m)           // 1. Zostaw tylko produkty >= 100 zł
    .OrderByDescending(p => p.Cena)       // 2. Posortuj od najdroższego
    .Select(p => p.Nazwa)                 // 3. Wyciągnij samą nazwę (string)
    .ToList();                            // 4. Zapisz gotowy wynik do List<string>

🔎 Niezbędnik metod LINQ

Metoda LINQ Co robi? Co zwraca?
.Where(x => warunek) Filtruje elementy spełniające warunek Sekwencja IEnumerable<T>
.Select(x => wynik) Przekształca (mapuje) każdy element na inną wartość Sekwencja IEnumerable<TResult>
.OrderBy(x => klucz) / .OrderByDescending(...) Sortuje rosnąco / malejąco (nie psuje oryginału!) Posortowana sekwencja
.FirstOrDefault(x => warunek) Zwraca pierwszy pasujący element albo null (0), gdy brak Pojedynczy element lub default
.Any(x => warunek) / .All(x => warunek) Czy choć jeden / czy wszystkie spełniają warunek bool
.Count(x => warunek) / .Sum(x => pole) Zlicza pasujące / sumuje wybraną właściwość int / decimal / double
.ToList() Uruchamia zapytanie i materializuje wynik w nowej List<T> List<T>
🔬 Pod maską: Deferred Execution (leniwe wykonanie) w LINQ i pułapka podwójnej iteracji LINQ & YIELD

Spójrz na poniższy kod - zawiera subtelną pułapkę, na której łapią się nawet doświadczeni programiści:

var liczby = new List<int> { 1, 2, 3 };

// W TEJ LINII nic się jeszcze nie policzyło! 'parzyste' to tylko PRZEPIS (zapytanie)!
var parzyste = liczby.Where(x => x % 2 == 0);

liczby.Add(4); // Dodajemy 4 DOPIERO PO zdefiniowaniu zapytania!

// Dopiero foreach lub .ToList() uruchamia przepływ danych:
foreach (var n in parzyste)
{
    Console.WriteLine(n); // Wypisze: 2 oraz 4!
}

Ten mechanizm nazywa się Deferred Execution (opóźnione / leniwe wykonanie). Metody .Where() i .Select() pod maską używają słowa kluczowego yield return - tworzą lekką maszynę stanów, która nie alokuje pośrednich list, tylko podaje elementy po jednym w locie.

Konsekwencja wydajnościowa: jeśli na tym samym zapytaniu parzyste (bez .ToList()) wywołasz najpierw parzyste.Count(), a linijkę niżej foreach (var x in parzyste), to filtr wykona się dwa razy od początku! Gdy planujesz użyć wyniku zapytania więcej niż raz, zmaterializuj go na końcu przez .ToList().

public static List<string> PobierzNazwyDostepnych(List<Pozycja> lista)
{
    return lista
        .Where(p => p.Ilosc > 0)
        .OrderBy(p => p.Cena)
        .Select(p => p.Nazwa)
        .ToList();
}

public static decimal SumaWartosciKategorii(List<Pozycja> lista, string kategoria)
{
    return lista
        .Where(p => p.Kategoria == kategoria)
        .Sum(p => p.Cena * p.Ilosc);
}

public static Pozycja ZnajdzNajdrozsza(List<Pozycja> lista)
{
    return lista
        .OrderByDescending(p => p.Cena)
        .FirstOrDefault();
}

public static bool CzyWszystkieDostepne(List<Pozycja> lista)
{
    return lista.All(p => p.Ilosc > 0);
}

🦾🐨🦾 Co masz wynieść z tej lekcji:

  • Wyrażenie lambda p => p.Cena > 100m to zwięzły zapis funkcji przekazywanej do metod LINQ (using System.Linq;).
  • Do filtrowania używaj .Where, do przekształcania .Select, do sortowania .OrderBy / .OrderByDescending, a do bezpiecznego pobrania pierwszego elementu .FirstOrDefault.
  • Zapytania LINQ są leniwe (Deferred Execution) - zakończ potok przez .ToList(), gdy chcesz od razu utrwalić wynik w pamięci i używać go wielokrotnie.
