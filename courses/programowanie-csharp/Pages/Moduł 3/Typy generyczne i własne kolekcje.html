Typy generyczne i własne kolekcje

Używałeś już List<int>, List<KontoBankowe> i Dictionary<string, KontoBankowe>. Zastanów się jednak: jak twórcy C# napisali klasę List<T>, żeby działała równie dobrze dla liczb, napisów i Twoich własnych klas, które dopiero wymyślisz?

Gdyby nie było typów generycznych, musiałbyś pisać osobne klasy MagazynInt, MagazynString, MagazynProdukt - albo wrzucać wszystko jako object, tracąc kontrolę typów i ryzykując awarie w czasie wykonania. Po tej lekcji sam zaprojektujesz własne klasy i metody generyczne <T> z ograniczeniami where.

🧬 Problem bez generyków: kopiuj-wklej albo niebezpieczny object

Spójrz na dwa złe sposoby napisania prostego pudełka przechowującego jedną wartość:

  • Zły sposób 1 (kopiowanie): piszesz PudelkoInt, PudelkoString, PudelkoKonto - potrójna robota przy każdej poprawce.
  • Zły sposób 2 (stary object): piszesz public class Pudelko { public object Zawartosc; }. Możesz tam wrzucić int, a potem przypadkiem spróbować wyjąć string - kompilator nic nie zauważy, a program wybuchnie dopiero u klienta z InvalidCastException!

Rozwiązanie w C# - parametr typu <T>:

public class Pudelko<T>
{
    public T Zawartosc { get; private set; }
    public bool CzyPelne { get; private set; }

    public void Wloz(T element)
    {
        Zawartosc = element;
        CzyPelne = true;
    }
}

// Jedna klasa, pełna kontrola typów przez kompilator!
var p1 = new Pudelko<int>();
p1.Wloz(42);
// p1.Wloz("tekst"); // BŁĄD KOMPILACJI! Kompilator chroni typ int!

var p2 = new Pudelko<string>();
p2.Wloz("Hasło");

🔒 Ograniczenia generyczne (Constraints: where T : ...)

Czasem Twoja klasa generyczna musi wiedzieć coś o typie T - na przykład, że T implementuje interfejs IRaportowalny albo jest klasą (class). Wtedy dopisujesz warunek where T : ...:

public class GeneratorRaportow<T> where T : IRaportowalny
{
    public string ZbudujLinie(T obiekt)
    {
        // Dzięki "where T : IRaportowalny" kompilator WIE, że obiekt ma metodę PobierzRaport()!
        return $"[RAPORT] {obiekt.PobierzRaport()}";
    }
}

🔎 Najczęstsze ograniczenia `where` w C#

Zapis Co gwarantuje kompilatorowi?
where T : class T musi być typem referencyjnym (możesz porównywać z null)
where T : struct T musi być typem wartościowym
where T : IRaportowalny T musi implementować interfejs IRaportowalny (możesz wołać jego metody!)
where T : new() T posiada publiczny bezparametrowy konstruktor (możesz wykonać new T())
🔬 Pod maską: Reified Generics w .NET - ile RAM oszczędza List<int> w porównaniu do ArrayList CLR & JIT

Porównaj w liczbach bezwzględnych, ile pamięci RAM zajmuje przechowywanie 1 000 000 liczb int w starej kolekcji niegenerycznej (ArrayList przechowującej object) oraz w generycznej List<int> w C# (architektura 64‑bitowa):

Kolekcja Sposób zapisu w pamięci Pamięć dla 1 000 000 int Praca dla Garbage Collectora
ArrayList (lub List<object>) Tablica 1 mln referencji (8 B) + 1 mln obiektów‑pudełek (24 B każdy) ~32 MB RAM Musi śledzić 1 000 000 osobnych obiektów!
List<int> (generyki .NET) Jedna ciągła tablica int[] (4 B na liczbę, zero boxingu) ~4 MB RAM Tylko 1 obiekt tablicy!

Dzieje się tak dzięki Reified Generics: w przeciwieństwie do Javy (Type Erasure, gdzie ArrayList<Integer> musi pakować każdą liczbę w obiekt), środowisko CLR zna typ <T> w czasie wykonania. Dla każdego typu wartościowego (int, decimal, struct) kompilator JIT tworzy osobny, natywny kod maszynowy bez żadnego boxingu, a dla typów referencyjnych (string, KontoBankowe) współdzieli jeden wspólny kod (bo każda referencja ma identyczny rozmiar 8 B).

💻 Zadanie praktyczne (2 pliki): Generyczny Stos i wyszukiwarka z ograniczeniem where

W pliku StrukturyGeneryczne.cs zaimplementuj dwie generyczne konstrukcje:

  1. Klasa MojStos<T> (struktura LIFO - Last In, First Out, jak stos talerzy):
    • przechowuje elementy w prywatnej liście private readonly List<T> _elementy = new List<T>();,
    • właściwość public int Liczba => _elementy.Count;,
    • public void Poloz(T element) - dodaje na koniec listy (_elementy.Add(element)),
    • public T Zdejmij() - jeśli stos jest pusty (_elementy.Count == 0) → rzuć InvalidOperationException, w przeciwnym razie pobierz ostatni element (_elementy[_elementy.Count - 1]), usuń go (_elementy.RemoveAt(...)) i zwróć.
  2. Klasa Raporter<T> where T : IRaportowalny:
    • metoda public List<string> ZbierzRaporty(List<T> obiekty) - dla każdego obiektu na liście wywołuje PobierzRaport() i zwraca List<string> z gotowymi raportami.
using System;
using System.Collections.Generic;

public interface IRaportowalny
{
    string PobierzRaport();
}

public class Zgloszenie : IRaportowalny
{
    public string Temat { get; }
    public Zgloszenie(string temat) { Temat = temat; }
    public string PobierzRaport() => $"Zgłoszenie: {Temat}";
}

class Program
{
    static void Main()
    {
        var stosLiczb = new MojStos<int>();
        stosLiczb.Poloz(10);
        stosLiczb.Poloz(20);
        Console.WriteLine($"Zdjęto ze stosu: {stosLiczb.Zdejmij()}"); // 20

        var raporter = new Raporter<Zgloszenie>();
        var linie = raporter.ZbierzRaporty(new List<Zgloszenie> { new Zgloszenie("Błąd sieci") });
        foreach (var l in linie) Console.WriteLine(l);
    }
}

public class MojStos<T>
{
    private readonly List<T> _elementy = new List<T>();
    public int Liczba => _elementy.Count;

    public void Poloz(T element)
    {
        _elementy.Add(element);
    }

    public T Zdejmij()
    {
        if (_elementy.Count == 0)
            throw new InvalidOperationException("Stos jest pusty.");
        int lastIdx = _elementy.Count - 1;
        T item = _elementy[lastIdx];
        _elementy.RemoveAt(lastIdx);
        return item;
    }
}

public class Raporter<T> where T : IRaportowalny
{
    public List<string> ZbierzRaporty(List<T> obiekty)
    {
        var wynik = new List<string>();
        if (obiekty == null) return wynik;
        foreach (T item in obiekty)
        {
            wynik.Add(item.PobierzRaport());
        }
        return wynik;
    }
}

🦾🐨🦾 Co masz wynieść z tej lekcji:

  • Gdy piszesz strukturę danych lub algorytm działający tak samo dla różnych typów, użyj parametru generycznego <T> zamiast kopiować klasy albo tracić bezpieczeństwo typów przez object.
  • Gdy wewnątrz klasy generycznej musisz wywoływać konkretne metody na T, dopisz ograniczenie where T : Interfejs (np. where T : IRaportowalny).
  • Generyki w C# działają w czasie wykonania bez boxingu dla typów wartościowych (int, decimal).
