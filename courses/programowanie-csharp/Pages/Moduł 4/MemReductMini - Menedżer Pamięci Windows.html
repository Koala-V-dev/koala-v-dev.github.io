MemReductMini - Menedżer Pamięci Windows

W poprzednich modułach opanowałeś klasy, enkapsulację, interfejsy, kolekcje, LINQ oraz zasady SOLID. Czas połączyć tę wiedzę w prawdziwe narzędzie systemowe dla Windows 11, które skompilujesz jako samodzielny plik MemReductMini.exe i uruchomisz na własnym komputerze bez uprawnień administratora.

Projekt jest inspirowany popularnym otwartoźródłowym narzędziem Mem Reduct (henrypp/memreduct). Zbudujesz wieloplikową aplikację, która:

  1. Odczytuje aktualne zużycie fizycznej pamięci RAM bezpośrednio z jądra Windows przez Win32 API (GlobalMemoryStatusEx).
  2. Wyszukuje procesy użytkownika zużywające najwięcej pamięci (Process.GetProcesses() + LINQ).
  3. Jednym uruchomieniem zwalnia nieaktywne strony pamięci (Working Set) wszystkich procesów bieżącego użytkownika przez Win32 API (EmptyWorkingSet), bezpiecznie omijając procesy chronione systemu.

🧠 Jak działa zarządzanie pamięcią w Windows (Working Set vs Standby List)

Zanim wywołasz funkcje systemowe Windows, musisz rozumieć, co tak naprawdę „czyści” program taki jak Mem Reduct. Pamięć RAM w Windows 11 nie dzieli się wyłącznie na „zajętą” i „wolną” - menedżer pamięci utrzymuje kilka list stron:

Obszar pamięci Windows Co się w nim znajduje? Czy wyczyścisz bez uprawnień admina?
Working Set procesu Strony fizycznej pamięci RAM przypisane aktualnie do konkretnego procesu (np. Chrome, Discord, VS Code). Tak - dla wszystkich procesów bieżącego użytkownika (EmptyWorkingSet)
Standby Page List Strony z cache plików i zamkniętych programów trzymane „na zapas” w RAM, gdybyś uruchomił je ponownie. Nie - wymaga uprawnień administratora i Native API (NtSetSystemInformation)
Modified Page List Zmienione strony czekające na zapis na dysk (plik stronicowania pagefile.sys). Nie - wymaga uprawnień administratora

W typowej pracy na laptopie lub w pracowni 70‑90% aktywnego obciążenia RAM to Working Set przeglądarek, komunikatorów i edytorów należących do Twojego konta. Dlatego EmptyWorkingSet z psapi.dll daje natychmiastowy, mierzalny spadek użycia pamięci nawet na szkolnym koncie bez uprawnień administratora.

🏗️ Architektura 4-plikowa zgodna z SOLID

Aby kod był czysty, testowalny w przeglądarce (na serwerze Linux/Mono) i jednocześnie w pełni funkcjonalny po pobraniu jako .exe na Windows 11, rozdzielamy go na cztery osobne pliki:

  1. RamSnapshot.cs - niemutowalny obiekt danych (enkapsulacja) przechowujący migawkę stanu RAM (TotalBytes, AvailableBytes, wyliczane właściwości UsedBytes, UsedPercent, UsedMb, TotalMb).
  2. IMemoryCleaner.cs - interfejs kontraktu (DIP / Strategia): CleanupReport CleanWorkingSets();.
  3. Win32MemoryEngine.cs - warstwa systemowa z P/Invoke do kernel32.dll (GlobalMemoryStatusEx) oraz psapi.dll (EmptyWorkingSet).
  4. Program.cs - punkt wejścia prezentujący stan RAM przed i po oczyszczeniu oraz listę Top‑5 procesów.

🔎 Wywoływanie natywnych bibliotek DLL Windows z C# (P/Invoke)

C# pozwala bezpośrednio wywoływać funkcje napisane w C wewnątrz systemowych bibliotek kernel32.dll i psapi.dll za pomocą atrybutu [DllImport] z przestrzeni nazw System.Runtime.InteropServices:

[DllImport("psapi.dll", SetLastError = true)]
private static extern bool EmptyWorkingSet(IntPtr hProcess);

Procesy systemowe (SYSTEM, antywirus) odrzucają dostęp do swojego uchwytu proc.Handle, rzucając wyjątek Win32Exception lub InvalidOperationException. Dlatego każda próba oczyszczenia procesu musi być osłonięta blokiem try / catch / finally (z wywołaniem proc.Dispose(), aby nie wyciekały uchwyty jądra!).

🔬 Pod maską: Co naprawdę robi EmptyWorkingSet, czym jest Soft Page Fault i efekt Bounce Back WINDOWS KERNEL & MEM REDUCT

1. EmptyWorkingSet nie „kasuje” danych aplikacji
Gdy wywołasz EmptyWorkingSet(proc.Handle), Windows nie niszczy kart w Chrome ani dokumentu w edytorze. Menedżer pamięci przegląda tablicę stron procesu i przenosi nieużywane ostatnio strony fizycznego RAM z jego Working Set na Standby List (dla stron czystych) lub Modified List (dla stron zmienionych).

2. Soft Page Fault vs Hard Page Fault

  • Jeśli po chwili wrócisz do okna przeglądarki, a jej strona nadal leży na Standby List w RAM, procesor zgłasza Soft Page Fault - jądro w ułamku mikrosekundy wpina tę samą ramkę RAM z powrotem do tablicy stron procesu (zero odczytu z dysku!).
  • Jeśli w międzyczasie inna aplikacja (np. gra lub maszyna wirtualna) potrzebowała tej pamięci, system bez zwłoki oddaje jej tę wolną ramkę. Gdy stara aplikacja będzie jej później potrzebować, odczyta ją z pliku stronicowania na SSD (Hard Page Fault).

3. Dlaczego henrypp/memreduct wymaga admina i czym jest efekt Bounce Back?
Pełny Mem Reduct oprócz Working Set czyści również globalną Standby List i System Cache wywołaniem nieudokumentowanej funkcji jądra NtSetSystemInformation(SystemMemoryListInformation, ...) z ntdll.dll, co wymaga przywileju SeProfileSingleProcessPrivilege (tylko Administrator).
Po każdym czyszczeniu RAM użycie pamięci będzie stopniowo wracać w górę (Bounce Back Effect) - to normalne zachowanie nowoczesnego systemu operacyjnego, który celowo wykorzystuje wolny RAM jako szybki cache dyskowy.

💻 Zadanie praktyczne: Zbuduj i pobierz własny MemReductMini.exe (4 pliki OOP)

Uzupełnij dwa miejsca w RamSnapshot.cs oraz Win32MemoryEngine.cs:

  1. W RamSnapshot.cs:
    • konstruktor RamSnapshot(ulong totalBytes, ulong availableBytes): jeśli totalBytes == 0 lub availableBytes > totalBytes → rzuć ArgumentOutOfRangeException,
    • właściwość UsedBytes zwracająca TotalBytes - AvailableBytes,
    • właściwość UsedPercent zwracająca ((double)UsedBytes / TotalBytes) * 100.0,
    • metoda CalculateFreedMb(RamSnapshot after) zwracająca ((double)after.AvailableBytes - AvailableBytes) / (1024.0 * 1024.0) (lub 0.0, gdy ujemna).
  2. W Win32MemoryEngine.cs:
    • w metodzie CleanWorkingSets() przejdź pętlą foreach po Process.GetProcesses(), wewnątrz try wywołaj EmptyWorkingSet(proc.Handle) (zliczając cleaned lub skipped), w catch zwiększ skipped, a w finally zwolnij zasób proc.Dispose().

Po zaliczeniu testów kliknij ⬇ Pobierz .exe (lub 🛠️ Skrypt .bat (Win11)) i uruchom własny program MemReductMini.exe na Windows 11!

using System;
using System.Diagnostics;
using System.Linq;

class Program
{
    static void Main()
    {
        Console.WriteLine("=== MemReductMini (Windows 11 User-Mode RAM Cleaner) ===");
        Console.WriteLine("Host: {0} | Rdzenie CPU: {1}", Environment.MachineName, Environment.ProcessorCount);

        var engine = new Win32MemoryEngine();

        if (Environment.OSVersion.Platform != PlatformID.Win32NT)
        {
            Console.WriteLine("[Tryb podgladu w chmurze Linux/Mono]");
            var demoBefore = new RamSnapshot(16UL * 1024 * 1024 * 1024, 5UL * 1024 * 1024 * 1024);
            var demoAfter = new RamSnapshot(16UL * 1024 * 1024 * 1024, 7UL * 1024 * 1024 * 1024);
            Console.WriteLine("Symulacja przed: {0}", demoBefore);
            Console.WriteLine("Symulacja po:    {0}", demoAfter);
            Console.WriteLine("Zwolniono:       {0:F1} MB", demoBefore.CalculateFreedMb(demoAfter));
            Console.WriteLine("Pobierz plik .exe lub skrypt .bat, aby uruchomic na swoim Windows 11!");
            return;
        }

        RamSnapshot before = engine.CaptureRamSnapshot();
        Console.WriteLine("RAM przed: {0}", before);

        Console.WriteLine("\nTop 5 procesow (Working Set):");
        var top5 = Process.GetProcesses()
            .OrderByDescending(p => p.WorkingSet64)
            .Take(5)
            .ToList();

        foreach (var p in top5)
        {
            Console.WriteLine("  - {0,-22} PID: {1,-6} {2,8:F1} MB", p.ProcessName, p.Id, p.WorkingSet64 / (1024.0 * 1024.0));
            p.Dispose();
        }

        Console.WriteLine("\nCzyszczenie Working Set procesow uzytkownika...");
        CleanupReport report = engine.CleanWorkingSets();
        RamSnapshot after = engine.CaptureRamSnapshot();

        Console.WriteLine("RAM po:    {0}", after);
        Console.WriteLine("Oczyszczono procesow: {0}, pominieto chronionych: {1}", report.CleanedProcesses, report.SkippedProcesses);
        Console.WriteLine("Zwolniono fizycznego RAM: {0:F1} MB", before.CalculateFreedMb(after));
    }
}

public class CleanupReport
{
    public int CleanedProcesses { get; private set; }
    public int SkippedProcesses { get; private set; }

    public CleanupReport(int cleanedProcesses, int skippedProcesses)
    {
        CleanedProcesses = cleanedProcesses;
        SkippedProcesses = skippedProcesses;
    }
}

public interface IMemoryCleaner
{
    RamSnapshot CaptureRamSnapshot();
    CleanupReport CleanWorkingSets();
}

using System;

public class RamSnapshot
{
    public ulong TotalBytes { get; private set; }
    public ulong AvailableBytes { get; private set; }

    public RamSnapshot(ulong totalBytes, ulong availableBytes)
    {
        // Zwaliduj: totalBytes == 0 lub availableBytes > totalBytes -> ArgumentOutOfRangeException
        TotalBytes = totalBytes;
        AvailableBytes = availableBytes;
    }

    public ulong UsedBytes
    {
        get { return 0; } // Zwróć różnicę TotalBytes - AvailableBytes
    }

    public double UsedPercent
    {
        get { return 0.0; } // Zwróć ((double)UsedBytes / TotalBytes) * 100.0
    }

    public double TotalGb { get { return TotalBytes / (1024.0 * 1024.0 * 1024.0); } }
    public double UsedGb { get { return UsedBytes / (1024.0 * 1024.0 * 1024.0); } }

    public double CalculateFreedMb(RamSnapshot after)
    {
        if (after == null) throw new ArgumentNullException("after");
        // Jeśli after.AvailableBytes <= AvailableBytes zwróć 0.0, inaczej różnicę w MB
        return 0.0;
    }

    public override string ToString()
    {
        return string.Format("{0:F2} / {1:F2} GB ({2:F1}%)", UsedGb, TotalGb, UsedPercent);
    }
}

using System;
using System.Diagnostics;
using System.Runtime.InteropServices;

public class Win32MemoryEngine : IMemoryCleaner
{
    [StructLayout(LayoutKind.Sequential, CharSet = CharSet.Auto)]
    private struct MEMORYSTATUSEX
    {
        public uint dwLength;
        public uint dwMemoryLoad;
        public ulong ullTotalPhys;
        public ulong ullAvailPhys;
        public ulong ullTotalPageFile;
        public ulong ullAvailPageFile;
        public ulong ullTotalVirtual;
        public ulong ullAvailVirtual;
        public ulong ullAvailExtendedVirtual;
    }

    [DllImport("kernel32.dll", CharSet = CharSet.Auto, SetLastError = true)]
    private static extern bool GlobalMemoryStatusEx(ref MEMORYSTATUSEX lpBuffer);

    [DllImport("psapi.dll", SetLastError = true)]
    private static extern bool EmptyWorkingSet(IntPtr hProcess);

    public RamSnapshot CaptureRamSnapshot()
    {
        var status = new MEMORYSTATUSEX();
        status.dwLength = (uint)Marshal.SizeOf(typeof(MEMORYSTATUSEX));
        if (!GlobalMemoryStatusEx(ref status))
        {
            throw new InvalidOperationException("Nie udalo sie odczytac GlobalMemoryStatusEx.");
        }
        return new RamSnapshot(status.ullTotalPhys, status.ullAvailPhys);
    }

    public CleanupReport CleanWorkingSets()
    {
        int cleaned = 0;
        int skipped = 0;

        foreach (var proc in Process.GetProcesses())
        {
            try
            {
                // Wywołaj EmptyWorkingSet(proc.Handle) i zaktualizuj cleaned lub skipped
                if (EmptyWorkingSet(proc.Handle)) cleaned++;
                else skipped++;
            }
            catch
            {
                skipped++;
            }
            finally
            {
                proc.Dispose();
            }
        }

        return new CleanupReport(cleaned, skipped);
    }
}

public class RamSnapshot
{
    public ulong TotalBytes { get; private set; }
    public ulong AvailableBytes { get; private set; }

    public RamSnapshot(ulong totalBytes, ulong availableBytes)
    {
        if (totalBytes == 0 || availableBytes > totalBytes)
            throw new ArgumentOutOfRangeException("availableBytes");
        TotalBytes = totalBytes;
        AvailableBytes = availableBytes;
    }

    public ulong UsedBytes { get { return TotalBytes - AvailableBytes; } }
    public double UsedPercent { get { return ((double)UsedBytes / TotalBytes) * 100.0; } }
    public double TotalGb { get { return TotalBytes / (1024.0 * 1024.0 * 1024.0); } }
    public double UsedGb { get { return UsedBytes / (1024.0 * 1024.0 * 1024.0); } }

    public double CalculateFreedMb(RamSnapshot after)
    {
        if (after == null) throw new ArgumentNullException("after");
        if (after.AvailableBytes <= AvailableBytes) return 0.0;
        return (after.AvailableBytes - AvailableBytes) / (1024.0 * 1024.0);
    }

    public override string ToString()
    {
        return string.Format("{0:F2} / {1:F2} GB ({2:F1}%)", UsedGb, TotalGb, UsedPercent);
    }
}

🦾🐨🦾 Co masz wynieść z tej lekcji:

  • Dzięki [DllImport] (P/Invoke) program w C# może bezpośrednio wywoływać natywne funkcje jądra Windows (GlobalMemoryStatusEx, EmptyWorkingSet) bez zewnętrznych bibliotek.
  • Na koncie bez uprawnień administratora można bezpiecznie oczyścić Working Set wszystkich procesów użytkownika, osłaniając procesy chronione blokiem try / catch / finally z proc.Dispose().
  • Oddzielenie logiki domenowej (RamSnapshot, IMemoryCleaner) od warstwy systemu operacyjnego (Win32MemoryEngine) pozwala testować aplikację niezależnie od systemu, a potem jednym kliknięciem skompilować ją jako MemReductMini.exe.
