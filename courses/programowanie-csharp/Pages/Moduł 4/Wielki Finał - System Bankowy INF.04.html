Wielki Finał - System Bankowy INF.04

Ten finał łączy w jednym projekcie wszystkie umiejętności z całego kursu: typy decimal, warunki if, pętlę foreach, Guard Clause, enkapsulację protected set, dziedziczenie : base, polimorfizm virtual / override oraz interfejs IRaportowalny. Zgodnie ze standardem dwupoziomowym zadanie podzielono na Część I (Podstawa Egzaminacyjna INF.04) oraz Część II (Wyzwanie Inżynierskie).

🏆 Część I (Egzamin INF.04): 4-plikowy System Kont z Limitem Debetu

W edytorze masz pełny projekt złożony z czterech plików:

  • Program.cs - kod uruchamiający raporty i wypłaty na wspólnej liście.
  • IRaportowalny.cs (tylko do odczytu) - wspólny kontrakt string PobierzRaport();.
  • KontoBankowe.cs (tylko do odczytu) - hermetyczna klasa bazowa z Saldo { get; protected set; }.
  • KontoFirmowe.cs - plik, który implementujesz samodzielnie!

🛠️ Wymagania egzaminacyjne dla KontoFirmowe.cs

  1. Klasa KontoFirmowe dziedziczy po KontoBankowe i implementuje interfejs IRaportowalny.
  2. Posiada właściwość tylko do odczytu public decimal LimitDebetu { get; }.
  3. Konstruktor KontoFirmowe(string wlasciciel, decimal saldoPoczatkowe, decimal limitDebetu):
    • przekazuje wlasciciel i saldoPoczatkowe przez : base(wlasciciel, saldoPoczatkowe),
    • jeśli limitDebetu < 0m, rzuca ArgumentOutOfRangeException.
  4. Przesłonięta metoda public override bool Wyplac(decimal kwota):
    • jeśli kwota <= 0m - rzuca ArgumentOutOfRangeException,
    • pozwala zejść z saldem poniżej zera aż do -LimitDebetu (czyli wypłata jest możliwa, gdy Saldo - kwota >= -LimitDebetu),
    • jeśli przekracza limit - zwraca false bez zmiany Saldo; w przeciwnym razie odejmuje Saldo -= kwota; i zwraca true.
  5. Metoda interfejsu public string PobierzRaport():
    • zwraca dokładnie $"Firma [{Wlasciciel}]: saldo {Saldo:F2} zł (debet do {LimitDebetu:F2} zł)".
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        var firmowe = new KontoFirmowe("TechSpółka", 200m, 500m);
        firmowe.Wyplac(600m); // Saldo schodzi na -400 zł (w limicie 500 zł)

        var raporty = new List<IRaportowalny> { firmowe };
        foreach (var r in raporty)
        {
            Console.WriteLine(r.PobierzRaport());
        }
    }
}

public interface IRaportowalny
{
    string PobierzRaport();
}

using System;

public class KontoBankowe
{
    public string Wlasciciel { get; }
    public decimal Saldo { get; protected set; }

    public KontoBankowe(string wlasciciel, decimal saldoPoczatkowe = 0m)
    {
        if (string.IsNullOrWhiteSpace(wlasciciel)) throw new ArgumentException("Brak właściciela");
        if (saldoPoczatkowe < 0m) throw new ArgumentOutOfRangeException(nameof(saldoPoczatkowe));
        Wlasciciel = wlasciciel;
        Saldo = saldoPoczatkowe;
    }

    public void Wplac(decimal kwota)
    {
        if (kwota <= 0m) throw new ArgumentOutOfRangeException(nameof(kwota));
        Saldo += kwota;
    }

    public virtual bool Wyplac(decimal kwota)
    {
        if (kwota <= 0m) throw new ArgumentOutOfRangeException(nameof(kwota));
        if (kwota > Saldo) return false;
        Saldo -= kwota;
        return true;
    }
}

public class KontoFirmowe : KontoBankowe, IRaportowalny
{
    public decimal LimitDebetu { get; }

    public KontoFirmowe(string wlasciciel, decimal saldoPoczatkowe, decimal limitDebetu)
        : base(wlasciciel, saldoPoczatkowe)
    {
        if (limitDebetu < 0m) throw new ArgumentOutOfRangeException(nameof(limitDebetu));
        LimitDebetu = limitDebetu;
    }

    public override bool Wyplac(decimal kwota)
    {
        if (kwota <= 0m) throw new ArgumentOutOfRangeException(nameof(kwota));
        if (Saldo - kwota < -LimitDebetu) return false;
        Saldo -= kwota;
        return true;
    }

    public string PobierzRaport()
    {
        return $"Firma [{Wlasciciel}]: saldo {Saldo:F2} zł (debet do {LimitDebetu:F2} zł)";
    }
}

🔬 Pod maską: Architektura Twojego systemu bankowego na tle wszystkich pięciu zasad SOLID ARCHITEKTURA & SOLID

W trakcie całego kursu nie tylko poznałeś składnię C# - zbudowałeś wieloplikowy system, który w praktyce spełnia zasady profesjonalnej inżynierii oprogramowania SOLID:

Zasada SOLID Gdzie wdrożyłeś ją w tym kursie? Dlaczego to chroni projekt?
S - Single Responsibility KontoBankowe pilnuje salda, Bank zarządza słownikiem i przelewami, IRaportowalny odpowiada za format tekstu Zmiana wyglądu raportu nie psuje przelewów
O - Open/Closed Dodałeś KontoOszczednosciowe i KontoFirmowe bez edycji ani jednej linijki w KontoBankowe.cs (readonly!) Rozwijasz system bez ryzyka zepsucia rdzenia
L - Liskov Substitution Każde KontoFirmowe i KontoOszczednosciowe działa poprawnie wszędzie tam, gdzie oczekiwane jest KontoBankowe Pętla foreach (KontoBankowe k in konta) nigdy się nie wywraca
I - Interface Segregation Mały, skupiony interfejs IRaportowalny z jedną metodą PobierzRaport() Klasy nie muszą implementować metod, których nie potrzebują
D - Dependency Inversion Kasa(IRabat) i List<IRaportowalny> zależą od interfejsu, nie od konkretnej klasy Błyskawiczne testy jednostkowe i podmiana zachowań

Wniosek inżynierski: to właśnie te zasady odróżniają skrypt napisany „na kolanie” od systemu, nad którym zespół programistów może pracować latami bez tonięcia w błędach.

🦾🐨🦾 Co masz wynieść z całego kursu:

  • Zaczynaj projektowanie od niezmienników danych: chroń stan przez protected set lub private i waliduj wejście przez Guard Clause na granicy każdej publicznej metody.
  • Rozróżniaj wartości od referencji, dziedziczenie („JEST”) od kompozycji („MA”) i od interfejsów („POTRAFI”).
  • Gdy kod przechodzi testy jednostkowe bez modyfikacji istniejącej klasy bazowej, wiesz, że Twoja architektura jest czysta, rozszerzalna i gotowa na egzamin INF.04.
